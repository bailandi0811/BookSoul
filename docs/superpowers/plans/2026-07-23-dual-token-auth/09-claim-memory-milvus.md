# CLAIM-02：访客记忆与 Milvus 认领

**目标：** 认领 Guest 会话时同步迁移文件系统记忆和向量归属，确保登录后记忆仍可检索。

**依赖：** MEMORY-01、CLAIM-01。

## 范围

- 迁移指定 session 对应的 profile 和长期记忆文件。
- 目标目录使用 JWT `sub`，不使用客户端用户 ID。
- 更新文件内部的 `userId` 元数据。
- 将 Milvus 对应记录的 `user_id` 更新为当前用户。
- 文件迁移和向量更新均支持重试与幂等。
- 定义部分失败状态、日志和再次执行策略。
- Milvus 不可用时允许 FS 迁移，但返回明确的降级结果。

## 不包含

- 迁移整个 Guest 的所有 session。
- 将向量或记忆正文迁入 PostgreSQL。

## 结果约定

接口应能区分 `completed`、`partial`、`already_claimed` 等状态。部分成功不能伪装为完全成功，前端应可据此提示重试。

## 验收清单

- [ ] 认领后用户可以读取原 Guest 的 profile 和长期记忆。
- [ ] 原 Guest 无法继续访问已迁移记忆。
- [ ] 用户语义检索仍能召回原 Guest 记忆。
- [ ] 重复执行不会产生重复文件或重复向量。
- [ ] 目标文件已存在时按确定规则合并或返回冲突。
- [ ] Milvus 不可用时返回 `partial`，并记录可定位但不含敏感信息的日志。
- [ ] Milvus 恢复后可安全重试并完成剩余迁移。

## 测试建议

- FS 正常迁移、目标冲突和重复迁移测试。
- Milvus 正常、不可用和更新失败测试。
- FS 成功但 Milvus 失败后的重试测试。
