# RELEASE-01：一期端到端验收与文档

**目标：** 在干净环境中可重复部署并验证一期完整用户旅程与安全边界。

**依赖：** AUTH-01 至 CLIENT-04 全部完成。

## 范围

- 增加或更新 `.env.example` 和 README 环境说明。
- 说明 PostgreSQL 创建、Prisma migration、Client 生成和服务启动方式。
- 补充一期端到端测试或可重复执行的验收脚本。
- 汇总各需求已有测试，不在本需求重复补单元测试债务。
- 检查 Token、密码和 Guest ID 日志脱敏。
- 标注生产环境必须收紧 CORS。
- 记录 Milvus 不可用时的降级行为和恢复步骤。

## 不包含

- OAuth、邮箱验证、找回密码。
- RBAC 和管理后台。
- httpOnly Cookie 改造。
- 聊天和记忆正文迁入 PostgreSQL。

## 端到端验收场景

- [ ] 在干净 PostgreSQL 上执行 migration 并启动服务。
- [ ] 首次打开生成 Guest ID，Guest 可以聊天和写入记忆。
- [ ] Guest 历史列表只能看到自己的会话。
- [ ] 注册后立即获得双 Token，并自动认领当前会话与记忆。
- [ ] 登录用户可以通过 `/auth/me` 获取当前资料。
- [ ] Access Token 过期后前端无感刷新并继续请求。
- [ ] 已轮换的旧 RT 无法再次使用。
- [ ] 当前设备登出后当前 RT 失效，其他设备保持有效。
- [ ] 全部设备登出后所有 RT 失效。
- [ ] 登出后回到新 Guest，界面不显示上一账号数据。
- [ ] 用户 A 无法读取、搜索、修改或删除用户 B 的 history / memory。
- [ ] RT 不能作为 Bearer Token 调用受保护 API。
- [ ] 日志不包含完整密码、AT、RT、Token 哈希或敏感路径。

## 交付物

- 可重复执行的数据库迁移。
- 后端与前端相关测试结果。
- 完整环境变量清单。
- 本地启动和验收步骤。
- 已知限制与二期范围说明。

上述验收项全部通过，且原始设计文档中的六项验收标准均有对应测试或人工记录后，一期才可标记完成。
