# AI 塔罗小游戏实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 实现登录后的独立塔罗小游戏，匹配已确认的分层纸面设计，提供真实服务端抽牌、流式解读和有界动效。

**Architecture:** 服务端独立 TarotModule 用 owner 为键的单进程内存状态保存许可证、问题、牌堆及揭晓顺序。客户端独立页面通过现有 apiFetch 调用四个端点，使用页面内存及取消/身份代次隔离。前后端从同一份静态牌组源生成各自可打包的数据，不共享业务状态。

**Tech Stack:** Node 22.19.x、npm、NestJS、现有 Zod / @langchain/openai、React 19、Zustand 认证状态、现有 Framer Motion、Jest、Vitest。

**Spec:** [AI 塔罗设计与验收契约](../specs/2026-10-05-ai-tarot-design.md)，包含本轮确认的视觉与动效。

## Global Constraints

- 不写数据库、Web Storage、单书聊天、检索、引用、记忆或公共聊天室；生产 JWT 认证仍复用现有账号认证状态校验。
- 不新增生产 npm 依赖，不修改现有 `.env`、部署配置、Prisma schema 或迁移。
- 按认证 owner 查询内存后再比对 permit / readingId，不相信请求体 owner。
- 许可证 10 分钟、局 30 分钟、每分钟清理、最多 1,000 份当前用户状态；仅单进程。
- 每用户每 10 分钟分类 10、洗牌 10、揭晓 30、解读 10；外部调用每用户 1、全局 20，不排队。
- Jev 超时 5 秒、无自动重试；解读 maxRetries=0、maxTokens=800、总截止时间使用 openai.requestTimeoutMs。
- 默认测试及质量门不连接数据库、向量库或真实供应商；不加载 `.env` 发起真实数据流。
- 保留当前混合检索相关未提交改动；按仓库规则直接在现有工作区实施，不创建分支、不提交、不 push。

## Review Focus

- 快速多次点击或重放旧 ID：权威揭晓顺序只能追加到 1/3 张，不能分叉、重洗或超额。
- 网络响应丢失：揭晓重试必须返回同牌，解读断流允许原局重试，不能暗中换牌。
- 重新占卜/退出/切账号：旧请求取消且晚到结果不能覆盖新状态，旧 finally 不得释放新运行占用。
- 局 TTL 与许可证 TTL 不同：许可证先过期不能清掉仍有效的已洗牌局，重试不延长 TTL。
- 逆位与动画：平面方向和 Y 轴翻转分层；减少动效、图片失败或动画中断不能阻塞后续操作。
