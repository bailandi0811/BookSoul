# BookSoul 章节阅读器设计

日期：2026-10-03。产品方向已在当前对话确认：首页点击图书先进入“本书空间”，再选择阅读或聊天；新增独立阅读模块、保留现有聊天页，在阅读器中保留可展开的助手面板，并通过正文按需加载与有界渲染控制前端开销。本书空间沿用全站背景、主题和封面样式。本文件与对应实施计划供实施前审阅，尚不代表功能已上线。

## 1. 任务契约

- **Goal：** 首页点击图书进入本书空间，由该页提供阅读与聊天两个独立入口；新增阅读器支持按需加载正文、连续阅读、自动续读、助手面板和引用回原文，现有聊天页保持可用。
- **Done：** 本文第 9 节的验收项全部有运行证据；未满足外部依赖或数据库隔离条件的检查明确记为未验证。
- **Scope：** 单书入口页 BookOverview、独立 BookReader 模块、章节正文接口、独立续读位置、排版设置、阅读助手面板、当前回答的引用跳转，以及必要的回归测试和文档。现有 BookChat 的页面结构和完整能力不被阅读器覆盖。
- **Risks：** 多窗口保存冲突、快速切书与旧响应、正文变化导致偏移失效、淘汰正文窗口与排版重排导致滚动跳位、手机布局与字体变化、读取权限与助手防剧透范围混淆。

本期不包含 EPUB 原版排版与插图、朗读、离线正文缓存、划线笔记、选段直问或段落级防剧透。第一版的“随时提问”使用现有聊天输入和会话；选段直问涉及可信选段校验与外部搜索隔离，另行设计。

## 2. 已核对的现状

- `server/prisma/schema.prisma` 的 `BookSection.content` 是完整的规范化章节正文；`BookChunk` 已有可空的 `startOffset/endOffset`。
- EPUB parser 已转为纯文本，不保留原书 HTML、插图和版式；本期直接读取该纯文本。
- `BookReadingService.listSections()` 只返回目录元数据；现有接口保持原样。
- `ReadingProgress.currentSectionOrder` 决定章节级 `spoilerCeiling`。`NOT_STARTED` 仍允许第 1 节，`FINISHED` 允许全书。
- `PRIVATE` 仅 owner 可见；`SYSTEM` 仅登录用户可读，助手、会话及进度仍归各用户所有。
- `useBooksStore` 当前管理 `library/workspace`；`useChatStore` 管理已有 SSE、停止生成与按书会话。
- 当前 `BookSessionsService.getHistory()` 只恢复角色和正文，不持久恢复引用元数据。本期不承诺让历史消息重新产生引用。
- 工作区已有前后端、认证、主题与文档改动；本期只在相关位置追加，不能覆盖或提交这些既有改动。

## 3. 用户流程

流程为 `首页书库 → 点击 READY 图书 → 本书空间 → 阅读 / 聊天`。首页仍负责完整书架、阅读概览与上传；点击书籍封面、标题或书卡进入当前书的 BookOverview，页标题为“本书空间”，不再使用“我的书架”或藏书总数。该页显示同一本书的封面、简介、续读位置与助手范围，并列提供“开始阅读 / 继续阅读”和“进入聊天 / 继续对话”。首页推荐书籍卡提供并列的“继续阅读”和“继续对话”快捷按钮：前者直接进入当前书阅读页，恢复独立续读位置；后者仍直接进入原聊天页。未就绪书籍不提供快捷按钮。

这一书卡导航变更由本轮最新要求明确确认，替代此前“书卡仍直接聊天、在书架增加阅读按钮”的方案。保留 `openBook()` 内部默认聊天契约，首页书卡显式传入 book 目标，避免顺带改变其他调用方。没有续读位置时从第 1 节开始，不根据助手的章节范围推断精确阅读位置。

本书空间提供“我的书库”返回入口；阅读和聊天提供“本书空间”返回入口。进入本书空间只加载展示所需的书籍元数据、独立续读位置与助手范围摘要，不请求正文、不准备聊天或创建会话。同书来回导航保留已存在的对话与草稿；换书和登出继续遵循作用域清理。

| 入口 | 页面职责 | 保留的能力 |
| --- | --- | --- |
| 图书 | BookOverview，标题“本书空间” | 当前书简介、位置与范围摘要、阅读/聊天入口、返回首页 |
| 阅读 | 独立 BookReader，以正文为主 | 目录、排版、续读、临时查看引用、可展开助手面板 |
| 聊天 | 现有 BookChat，以对话为主 | 当前页面布局、会话历史、助手设置、引用、邮件、外部研究与停止生成 |

2026-10-04 用户确认阅读页采用更圆润、有层次的独立卡面：左侧书籍、目录和续读位置分别成卡；中央章节导航与正文卡分开；右侧是工具和按需展开的助手卡。书籍卡沿用现有封面绑定，背景和主题沿用顶部外观控件。正文只占一张不透明的大卡片，所有章节在卡片内部连续上下滚动，章节之间保留标题与留白，不拆成独立卡片。提供书名、上一章 / 下一章、排版设置、助手入口和返回本书空间。临近章末预取下一章开头，向上回看按需加载前章末尾；顶部章节和续读记录依据实际可见正文更新，预取本身不改写续读位置。正常保存到更后的章节时，已读进度和助手范围一起抬高；临时翻看不扩大。正文不随滚动做入场动效，卡面悬停、面板开合与工具操作采用短时透明度、位移和按压反馈；减少动态效果设置取消位移、缩放和持续动效。

桌面宽度不小于 1024px 时助手在右侧按需展开，默认关闭，面板宽度 340px，1024—1279px 时为 300px；1280px 起默认展示目录，打开助手收起目录列表，书籍和续读位置卡仍保留。目录和助手不动画改变栏宽，重排保持正文文字锚点。较窄屏幕使用底部工具栏，目录、排版和助手采用可关闭的对话面板，复用现有 Dialog 的焦点管理。关闭面板恢复触发按钮焦点和正文位置；若正在生成，调用现有停止生成能力，保留已收到的回答和草稿。

阅读器另提供“进入聊天页”快捷入口，面板只是当前书助手的简洁入口，不能代替现有完整聊天页。首次打开阅读器且未展开面板时不加载聊天历史、不创建会话、不启动模型调用。首次展开面板或进入聊天页时才准备当前书的聊天状态；已有同书状态时不重复 `prepareBook()`、清空消息或草稿。只有切换到另一书的聊天作用域时才准备新书；登出清理所有私有状态。离开聊天或收起面板导致生成界面不可见时停止生成，保留已收到内容。

## 4. 阅读、续读与防剧透的语义

屏幕位置、续读位置和已读进度仍然分开保存，但用户能感知的“读到哪里”只有已读进度这一个数，它同时是助手的讨论上限。

| 状态 | 用途 | 推进方式 |
| --- | --- | --- |
| 屏幕正在展示的位置 | 浏览与引用定位 | 滚动、目录或引用导航 |
| 续读位置 | 下次打开的精确文字位置，可以停在比最远已读更早的章节 | 正常阅读的用户滚动，以及显式“从这里继续阅读” |
| 已读进度 | 书架上的“读到哪里”，并限制检索、生成和引用 | 续读位置成功保存到更后章节时单调抬高；也可在进度对话框明确修改 |

正文阅读允许用户主动进入任一有权访问的 READY 章节；否则用户无法继续读下一章。临时翻看、预取和尚未确认的屏幕位置不进入模型上下文，也不提高已读进度。

正常保存第 18 节后，已读进度和 `spoilerCeiling` 变为 18；若原先已是更后的章节或“已读完”，则保持不变。临时浏览第 18 节不保存续读位置，上限也不变。回看更早章节只移动续读位置。进入最后一章不自动标成读完。界面显示“可讨论到第 N 节”，并说明当前采用章节级限制：允许第 N 节等于允许整节，而非只允许已看到的段落。阅读器只保存续读位置，不另调进度接口。

从引用或目录进入采用临时浏览模式，不写回续读位置，提供“返回续读位置”和“从这里继续阅读”。上一节 / 下一节沿用当前模式。临时浏览模式下排版变化、滚动、自动定位同样不能触发持久保存。

全书单次放行不修改续读位置或长期助手范围。引用跳转到当前助手范围之后时，显示“打开会显示后文”的明确提示，用户确认后进入临时阅读；不能把这次确认转为聊天的 `spoilerOverride`。

## 5. 正文与引用接口

新增控制器与服务放在 `server/src/books/`，复用 JWT/AuthContext 和现有 PRIVATE/SYSTEM 规则。所有查询先包含当前 owner 可访问的 book 条件，再在章节或片段查询中限制 `bookId`、READY 状态和必要的 active embedding version；不得凭 sectionId/chunkId 单独取出数据后补做归属校验。

### 5.1 正文窗口

`GET /api/books/:bookId/sections/:sectionId/content?offset=0&limit=16000`

响应沿用 `{ success: true, data }`，`data` 为：

```typescript
interface SectionWindow {
  bookId: string;
  sectionId: string;
  sectionOrder: number;
  sectionTitle: string;
  contentHash: string;
  totalLength: number;
  startOffset: number;
  endOffset: number;
  text: string;
  nextOffset: number | null;
}
```

所有位置为规范化正文中的 UTF-16 code unit 偏移，与现有 JS `slice()` 和 chunk offset 一致；范围左闭右开。`contentHash` 是整节规范化正文 UTF-8 字节的 SHA-256，不包含用户身份或路径。

`offset` 必须是 0 到正文长度之间的安全整数；`limit` 默认 16000，范围为 1024—32000。窗口边界不能截断代理对：起点位于低代理项时回退 1；终点位于一对代理项中间时回退 1。响应里的实际范围为准，下一请求使用 `nextOffset`，不能按请求长度自行累加。

正文通过文本节点渲染，保留原有换行与空格，不二次 trim/normalize，不执行 HTML、脚本、Markdown 或资源链接。浏览器内存和 DOM 最多保留当前及相邻的 3 个正文窗口，其余采用占位布局；换书和登出清理缓存。响应使用 `Cache-Control: private, no-store`，不进入 localStorage、IndexedDB 或 Service Worker。

### 5.2 引用定位

`GET /api/books/:bookId/chunks/:chunkId/location`

返回 `bookId/sectionId/sectionOrder/contentHash/startOffset/endOffset/precision`。有效偏移且 `section.content.slice(startOffset,endOffset) === chunk.content` 时，定位并高亮对应片段开头至多 600 个 code unit，终点同样避开代理对，`precision="excerpt"`。无有效偏移时返回 `startOffset=0/endOffset=0/precision="section"`，界面说明“已定位到章节，无法精确高亮”。

只定位当前 active embedding version 的片段。重建后旧片段不存在返回 404，保留原引用卡片，提供按原 sectionId 查看章节的入口；章节也不存在时显示不可用。重复原句不能用字符串搜索猜测定位。无需修改现有 SSE 事件、ChatDto、检索策略或历史数据格式。

两个接口未认证返回 401；不存在或属于他人的私有资源返回 404；可访问书籍非 READY 返回 409；无效范围返回 400。查询异常不能伪装成空正文。

## 6. 续读位置与保存契约

新增 `BookReadingPosition`。`ReadingProgress` 的表结构不变；确认保存续读位置时，按下面的规则更新其中的已读进度：

| 字段 | 定义 |
| --- | --- |
| ownerId + bookId | 复合主键，来自服务端认证和已授权书籍 |
| sectionId | 当前续读章节，关联 BookSection，删除章节时级联清理位置 |
| offset | 屏幕正文顶部附近的文字偏移，非滚动像素，非整书百分比 |
| contentHash | 保存时对应正文 hash |
| revision | 服务端递增版本，首次成功创建为 1 |
| updatedAt | 服务端更新时间 |

owner、book、section 外键均有确定的删除行为，删除书籍或账号清理对应续读位置，不保留孤儿记录。最初的位置迁移只新增表、索引和约束，不重置或重写既有进度，不改已应用迁移。

2026-10-04 起，续读位置保存成功且该书不是“已读完”时，在同一事务内把已读进度抬到 `max(当前章节, 这次保存的章节)`。没有进度时写成“阅读中”。条件更新使用数据库中的较大值，后到达的旧窗口不能把进度写小。位置冲突或正文 hash 不一致时进度不变。读取位置不写数据库。保存成功的响应在续读位置上附带进度摘要（`mode`、`currentSectionOrder`、`updatedAt`、`spoilerCeiling`）。手动把进度改低后，下一次在更后章节确认阅读会再次抬高；手动改低不能变成长期独立的助手范围。

已有续读位置用单独迁移只升不降回填：位置所在章节更后、且状态不是“已读完”时，改为该章节的“阅读中”。没有续读位置、已经更后或已经读完的记录不动。该迁移须在核对目标库后单独部署，测试和默认检查不执行它。

- `GET /api/books/:bookId/reading-position`：返回 `ReaderPosition | null`。对象包含以上字段的安全摘要与 `contentChanged: boolean`；不返回 ownerId，也不返回进度摘要。读取不创建位置，不修改进度。
- `PUT /api/books/:bookId/reading-position`：body 只含 `{sectionId, offset, contentHash, expectedRevision}`。首次保存 `expectedRevision=0`；此后必须匹配当前版本。成功响应额外包含 `readingProgress`。
- 保存验证章节属于当前书、偏移有效、hash 与当前正文一致。版本通过数据库条件更新原子比较并递增；禁止“先读版本，再无条件 upsert”。首次创建竞争只允许一个成功，另一个返回 409。
- hash 不一致返回 `409 READER_CONTENT_CHANGED`；版本冲突返回 `409 READER_POSITION_CONFLICT`。客户端保留当前屏幕，读取最新版本，显示冲突并让用户明确选择“使用本窗口的位置”，不自动覆盖其他窗口的进度。

正常阅读在用户停止滚动 1 秒后保存最新可见文字位置；同一 owner/book 的保存串行合并，旧请求不能晚到覆盖新位置。自动恢复滚动、排版重排和临时浏览不保存。离开页面时尽力提交未保存位置，但不承诺强制关闭浏览器前的最后 1 秒必然保存。

位置保存失败显示“位置尚未保存”，保留本窗口待保存位置，提供重试。刷新只恢复服务端确认的位置；不把失败状态伪装成跨设备保存成功。hash 变化时回到该节开头，说明“正文已更新，原位置无法恢复”，保留当前 revision，下一次用户正常阅读后保存新 hash；不得静默沿用旧 offset。

## 7. 前端职责与排版

- `useBooksStore` 增加 book、reader 视图，保留默认 `openBook()` 进入现有聊天的兼容行为；首页书卡显式选择 book 目标，首次进入 book/reader 不准备聊天。新增明确的阅读/聊天导航，只有打开助手面板或进入聊天页才确保当前书聊天状态；同书状态不重复初始化。打开书籍与进度写回加请求代次保护，清理状态使旧代次失效。
- 新增 BookOverview 单书入口页，复用现有 AppHeader、ScenicBackground、BookCover 与 useAppearanceStore。背景选择和明暗主题由全局状态管理，导航不能重置外观，也不新建仅本书空间使用的背景存储。沿用当前半透明纸面、圆角、字体和封面绑定；正文区域保持足够遮罩保证可读性。背景面板支持键盘、Escape 和焦点返回。
- 新增 `useReaderStore` 管理正文窗口、续读位置、临时浏览、保存队列和请求取消。保存成功后把响应里的进度摘要写入书籍状态；它不自行计算助手范围，也不管理模型生成。旧响应不能覆盖更新的进度。
- 新增独立 `BookReader` 页面与正文窗口、目录、排版工具栏、助手面板组件。ReaderAssistantPanel 复用现有 InputArea、MessageBubble 与同一 useChatStore，不把完整 BookChat 嵌入阅读器、不改变其页面布局，也不复制第二套聊天状态或 SSE 实现。现有聊天页只增加必要的阅读快捷入口和引用跳转连接。
- 排版偏好只存非私有的字号、行距与宽度：字号 16—28px，默认 20px；行距 1.6—2.2，默认 1.9；阅读宽度 480—800px，默认 640px，窄屏按可用宽度收缩。主题与背景沿用现有外观系统。
- 每个正文段或文字节点保留其绝对偏移。测量和恢复使用 DOM Range 与正文节点的映射；长段落也恢复到原文字行附近，不能只记录段首。
- 字号、行距、宽度和屏幕尺寸变化前记录文字锚点，重排后恢复；不把变化后的像素值当成新的阅读位置。
- 新的目录、工具栏与面板支持键盘、可见焦点和可访问名称；手机不采用横向挤压的双栏布局。

### 7.1 按需加载与渲染

- **页面代码按入口加载：** App 使用 React.lazy 动态导入 BookReader，继续保留现有 BookChat 的懒加载；仅停留书架不下载阅读器专属模块。
- **正文按章、按文字窗口加载：** 打开一本书只请求目录、独立位置和首个所需正文窗口，不下载全书，也不将长章节一次传到浏览器。请求当前窗口附近内容，距离已加载内容末端约一个视口时预取下一窗口。
- **预取有界：** 同一阅读作用域最多一个前台窗口请求和一个相邻窗口预取。相同 owner/book/section/hash/offset 的并发请求合并，不能因多次 scroll 或 observer 回调重复发送。仅预取当前正文窗口附近内容，可跨相邻章节，不自动预取全书。预取发起前和返回后均核对拟淘汰窗口是否包含当前可见文字；快速反向滚动时保留眼前正文，避免短章被连续预取挤出。
- **DOM 与缓存有界：** 最多保留当前和前后相邻共 3 个窗口，其他区域保留已测量高度的占位；删除旧正文节点不能使当前文字跳位。回滚时按需重新加载已淘汰窗口，不能为回看永久积累正文节点。
- **滚动处理轻量：** 使用 IntersectionObserver 触发临近窗口加载，几何测量最多每 animation frame 一次；排版与存储更新不随每一个 scroll 事件触发整页重渲染。自动重排继续按文字锚点恢复。
- **作用域与取消：** 换书、换章节、登出后取消旧前台/预取请求，使旧回调失效；缓存键含身份代次和书籍/章节/hash。阅读页未展开助手时不初始化聊天、加载历史或调用模型。
- **加载失败可见：** 下一窗口失败保留当前正文与锚点，在边界显示重试；同一窗口不无界自动重试。断网或预取失败不能用假文本补齐章节。

正式验收以 80000 code unit 的合成单节和多章节小说为输入：请求日志证明未请求全书或全部章节，单次正文不超过 32000 code unit；正文窗口 DOM 不超过 3 个。滚动和切书检查重入、取消与锚点；浏览器 Performance 面板检查是否存在本功能产生的持续主线程长任务。记录测试设备、条件和实际现象，不在没有真实测量时承诺固定帧率。

## 8. 验证边界

单元与前端流程测试全部使用合成小说、mock Prisma、mock fetch 和固定 SSE，默认质量门不连接实际数据库、向量库、模型或上传目录。

真实 CAS/外键验证仅在专用 reader 数据库测试中运行，复用 `resolveIsolatedDatabaseUrl(process.env)`。调用者显式提供 TEST_DATABASE_URL 与用于比对的 DATABASE_URL；必须证明独立 `*_test` 数据库和 `test_*` schema。新建 reader 专用 Jest 配置与脚本，不能把测试混入默认发现范围。fixture 清理只针对本次创建的稳定 ID。

迁移部署不包含在“写计划 / 本地实现”授权中。执行者在获准目标上核对备份和迁移内容后单独部署；不得借运行测试对开发库执行迁移。数据库测试缺少预先迁移的隔离库时记为未运行。

浏览器排版验收使用独立测试 HTML 和合成数据拦截器；它不能发送请求到现有 Vite /api 代理。该验收证明浏览器布局与交互，不替代真实 NestJS/数据库契约测试。真实模型闭环另需用户授权及外部依赖，不能自动运行现有带 fixture 删除的 reader E2E。

## 9. 验收条件

1. READY 的 EPUB/TXT 和 SYSTEM 书均可阅读；401/404/409 拒绝路径可观察且无正文泄漏。
2. 超过 64000 code unit 的单节可以滚动阅读，窗口衔接不丢字、不重复，emoji 不损坏，正文 DOM 至多 3 个窗口。
3. 正常阅读确认保存后刷新，恢复到原文字行附近；改变字号、主题和屏幕宽度保持文字锚点。
4. 快速 A→B 切书、登出、账号切换后，A 的晚到正文或保存响应不能写进 B 或恢复私有界面。
5. 两个窗口用同一 revision 保存，数据库中只有一个成功；失败窗口显示冲突，不能自动覆盖。
6. 临时查看目录或引用后返回，原续读位置不变；显式“从这里继续阅读”后才改写。
7. 首页书卡进入当前书的“本书空间”，该页阅读、聊天入口分别进入 BookReader 与原 BookChat；首页“继续对话”快捷入口仍直接聊天，原聊天页完整能力不回归。进入 book/reader 不准备聊天；展开阅读助手才复用当前书会话，同书切换、面板关闭与重开不丢草稿和已收到回答，停止生成仍可达。
8. 新引用定位按片段偏移高亮；无偏移或旧版本片段提供明确的降级说明，不猜位置。
9. 正常保存第 18 节后，检索上限变为 `sectionOrder <= 18`；临时浏览第 18 节时上限不变，阅读器不调用进度更新接口。回看更早章节不降低已有上限，“已读完”保持不变。
10. 375×812、768×1024、1440×900 的明暗主题均无页面水平溢出；正文、目录与面板可用键盘操作。
11. 初次阅读不请求全书或未进入的章节；临近窗口预取不重复、不越界，长期滚动窗口数量有界。下一窗口失败可重试且当前正文不丢失，切书后的旧窗口响应不能污染新书。
12. 本书空间的背景与主题可通过同一顶部控件调整；在首页、本书空间、阅读和聊天之间切换，外观选择保持一致。同书封面颜色和图案不变；手机背景面板无水平溢出，Escape 返回触发按钮。

实施顺序、对应文件、测试命令及验收记录格式见[实施计划](../plans/2026-10-03-novel-reader.md)。
