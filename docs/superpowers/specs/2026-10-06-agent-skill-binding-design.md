# Agent 与 Skill 显式绑定设计

**日期：** 2026-10-06  
**状态：** 用户已批准设计和实施计划；已实施并通过服务端完整检查，98个文件／651例测试。独立审查发现的边界问题已修复；结果见[验收记录](../../tarot-acceptance.md)。  
**范围：** BookSoul 服务端运行时，先接入塔罗选阵与解读两个入口，建立未来 skill 的统一接入约束。

## 1. 目标和隔离含义

用户要求指定 Agent 可以加载、使用对应 skill，其他 Agent 不自动触发、不受其中指令或流程影响，新 skill 同样显式管理。

- Goal：skill 的可见性、加载权限和注入位置由服务端代码决定，而不是由名称匹配、模型决定、用户参数或全局目录发现决定。
- Done：两种塔罗角色的绑定可查；跨角色加载、未知 skill 和未授权新增 skill 被拒绝；拒绝发生在读取内容与模型调用之前；无相关 skill 的其他 Agent 请求不发生变化。
- Scope：统一管理的纯 TypeScript 模块、现有两处塔罗加载入口、相邻测试、项目接入规范及验收记录。
- 非目标：管理 Codex/Claude 开发工具的全局技能、添加 skill 市场/上传/编辑后台、给模型暴露通用 skill 执行工具、重构单书 Agent、改动牌阵/牌义/模型参数/选阵门槛、替换供应商、数据库迁移。
- Risks：同进程内的应用隔离不能当作操作系统安全隔离。测试证明受控加载路径及模型上下文隔离，不保证任意后端代码或拥有任意文件读取权限的工具无法读取源文件。

关闭自动调用仅意味着不通过关键词或自动扫描触发，不能代替授权。此方案的应用隔离还包含：未授权目录不可见、访问被拒绝、skill 指令不进入上下文、没有由 skill 间接取得的额外工具权限。若未来允许运行不可信 skill 代码或提供任意文件系统能力，应另行设计独立进程、文件挂载和网络权限；本轮不声称已有这种边界。

## 2. 当前事实与方案选择

目前选阵由 `tarot-selection.rules.ts` 的 `buildTarotSelectionQuestion()` 构造 Choice 策略，解读由 `tarot-reading.prompt.ts` 直接加载 `tarot-reading.rules.ts`；没有全局 skill 扫描，也没有可供模型调用的 skill 管理工具。两者在 `TarotProviderService.classify/read` 中分别使用，属于独立运行职责，不需要为“Agent”称谓另建 LangGraph 子系统。

可选路径：

| 路径 | 效果与取舍 |
| --- | --- |
| 只在文件注释声明所属 Agent | 轻便，但无法拒绝未授权加载，也无法验证新增 skill 的规则 |
| 显式绑定清单＋受控加载＋源码边界检查 | 推荐；符合当前可信代码、固定角色与本地规则，无新依赖或外部调用 |
| 每个 Agent 独立进程或容器 | 能提供额外系统边界，增加部署与取消/超时管理；当前没有执行不可信代码的需求 |

采用第二条，不创建第二套聊天服务、会话或持久化系统。

## 3. 角色、Skill 和绑定

Agent 标识表达业务职责，不使用供应商模型名代替身份；同一个模型也可以服务不同职责，身份由服务端入口决定。

| Agent ID | 业务入口 | 唯一允许的 Skill ID | 内容 |
| --- | --- | --- | --- |
| `tarot-selector` | `TarotProviderService.classify` | `tarot-spread-selection` | 当前四选项 Choice 策略，沿用 spread-selection-v2 |
| `tarot-interpreter` | `buildTarotReadingMessages`，被 `read` 使用 | `tarot-reading` | 公共解读规则＋当前局牌阵专用规则，沿用 spread-routing-v2 |
| 其他运行职责 | 当前原有业务入口 | 本轮不授予上述 skill | 继续使用现有实现，不新增塔罗指令 |

解读公共规则是 `tarot-reading` 的内部组成部分，不是全局自动加载 skill。三个牌阵规则不是三个默认同时注入的 skill，仍按服务端权威 spread 选择当前的一组。

Skill 定义包含稳定 `id`、`version`、简短 `description`、内容类型及内部加载函数。绑定表显式列出 Agent 与允许的 skill；未知 Agent 默认没有权限，新 skill 注册不自动获得任何绑定。清单与绑定均只由受信任源码维护，不接受 HTTP 请求、用户问题、模型输出或 SKILL.md 文本覆盖。

本轮 skill 是策略内容，不是可执行工具。所谓“调用 skill”指业务入口授权加载并显式用于本次模型请求；不添加工具调用、递归加载或 skill 自己扩展权限的机制。以后如需可执行工具，须单独定义工具 allowlist、参数 schema 和副作用许可，skill 绑定不自动授权工具。

## 4. 模块与加载路径

新增 `server/src/agent-skills/`，管理类型、内部目录、绑定表、校验和面向业务入口的受限访问端口。规则内容仍由 `server/src/tarot/` 维护。管理模块不导入现有 AgentModule、数据库、RAG、Memory 或工具服务，不需要新增 Nest module/provider。

```text
受信任分类入口 → selector 专用端口
               → 验证 skill 绑定 → 加载选阵策略 → 当前 Jev Choice 请求

受信任解读入口 → 校验当前局牌阵与牌单 → interpreter 专用端口
               → 验证 skill 绑定 → 公共＋当前牌阵规则 → 当前局两条消息
```

- 核心授权检查支持元数据列举和内容加载，但内部目录及任意 Agent ID 工厂不作为业务公共 API 导出。业务调用方只使用固定角色端口；不提供可由用户控制的 `loadSkill(agentId, skillId)` 接口。
- 身份在服务端入口固定，不能从 request body、state、模型工具参数或输出中读取。专用端口不能借参数切换到其他 Agent 身份。
- 先检查 Agent/Skill/绑定，再运行内容加载函数。未知与未授权访问返回不同的稳定内部错误码，不调用加载器或供应商，不静默补默认技能。
- 目录校验检查重复 ID、缺失版本、不存在的绑定目标和非法内容类型。绑定缺陷应显式失败，不被分类供应商 unavailable 的 catch 伪装成网络异常。
- 未授权 Agent 列举结果不包含该 skill 的元数据或正文。模型不接收完整目录、绑定表或管理规则。
- 返回不可变或独立内容，避免一个运行修改共享对象后影响另一个运行；本轮不增加缓存。现有 owner/session/round 隔离保持原样。
- 提示词位置仍按现有契约：选阵策略进入 Choice instructions/criteria；解读规则进入 system，当前问题与牌单进入独立 user 数据。模型或不可信输入不能改变加载列表。
- 不通过文件目录名或 frontmatter 建立权限，不自动扫描本地全局 skill 文件，不自动跟随 skill 中的链接、依赖或加载其他 skill。

## 5. 防止直接导入绕过

加载授权不能只靠调用方自觉。新增源码边界检查，使用现有 TypeScript 能力检查本轮规则/目录/内部管理接口的 import、re-export 与常量模块加载路径：

- 规则内容只允许本轮指定的目录适配器及相邻离线测试直接读取。
- 业务运行入口改用对应受限端口；其他运行模块不能直接导入塔罗规则、内部目录或任意身份工厂。
- 受限端口只能被清单中的业务入口使用，新增消费者必须同时显式更新清单及测试。
- 测试提供一个违规导入的负例，证明检查会失败；默认质量门执行此检查。

这是源码维护和受控运行路径边界，不是 JavaScript 模块系统的防恶意代码沙箱。动态任意路径读取、任意代码执行不得以“通过绑定测试”为理由向模型开放。

## 6. 不变量与可观测性

现有选阵 instructions/criteria 及解读 system/user 内容保持等价，不因管理重构改变业务规则版本。HTTP 字段、四选项、confidence>=0.8、牌位、SSE、两条当前局消息、取消、deadline、maxRetries=0 和输出上限均保持。

沿用已有 runId，在既有阶段日志中补充固定 agentId、skillId、skillVersion 即可。不记录 skill 正文、用户问题、牌面、token 凭据或用户标识；不新建持久日志表，也不将跨 Agent 数据送入模型。

## 7. 验收

1. 正向：selector 仅可见并加载 selection；interpreter 仅可见并加载 reading。解读只返回当前牌阵规则。
2. 拒绝：互相加载、未知 Agent、未知 Skill、注册但未绑定的新 skill 均拒绝，加载器和模型调用次数为零；不存在的绑定目标被校验拒绝。
3. 身份：用户问题与伪造工具输出中的 agentId/skillId 不影响绑定；业务公开端口不能接收自由 Agent ID。
4. 污染：修改一份返回内容不影响下一次调用；selector 的请求不含 reading 内容，interpreter 不含 selection 内容；连续混合局仍只有当前局消息。
5. 边界：源码检查发现直接导入/转导出绕过；既有单书 Agent 未导入本轮 skill 或受限端口，保持其代码与模型请求构造不变。
6. 回归：现有塔罗 provider/prompt/state/controller 与隔离/取消测试通过，不以模型逐字输出作为断言。
7. 质量门：相关 Jest → 默认测试发现范围与数据库安全检查 → server/npm run check → diff。客户端、配置、数据库与部署不改，不运行真实供应商验收来验证纯加载关系。

## 8. 新 Skill 接入规则

新增 skill 时必须明确：稳定 ID 与版本、所属业务模块、内容/能力类型、允许的 Agent、注入位置、依赖与外部副作用、拒绝路径测试。只创建文件或注册目录不足以启用；只有显式绑定和受限端口接入后才会生效。

共享 skill 必须分别授权每个消费者，无全局继承。解绑后列举与加载都不再允许；部署版本变化后开始的新运行使用新清单，不增加热更新或跨部署运行迁移机制。文档放在项目 Agent/Skill 管理主题下，AGENTS.md 仅添加简短规范和入口链接，不复制完整清单。

保留工作区现有改动，不创建分支/提交，不改 .env、依赖、CI、单书业务和用户数据。本轮不包含外部付费调用。规则版本保持不变，只有绑定能力形成新工程契约；不以命名隔离或一句系统提示词宣称真正的系统沙箱。
