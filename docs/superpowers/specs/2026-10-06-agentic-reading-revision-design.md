# 书籍助手 Agentic RAG 修正设计

更新日期：2026-10-07。状态：已实施，真实供应商验收未运行。用户要求深度模式提高检索与回答准确率，按需调用记忆、MCP 和工具，不强迫每题拆解和多轮思考。本文及[执行计划](../plans/2026-10-06-agentic-reading-revision.md)取代旧深度设计中的固定 plan/check 流程、5 秒模型期限及“深度禁用记忆/工具”限制；快速模式保持当前契约。

## 1. 任务契约

**Goal：** 深度模式成为保留完整助手能力的有界 Agentic RAG：已有原文足够就回答，存在缺口才自主改写查询或召回其他已授权资料。

**Done：** 无需新事实的对话可一次主模型调用直接结束；单点事实问答通常一次检索、两个主模型回合完成（请求工具、依据原文回答）；复杂问题可按需补检；当前书记忆与全局阅读偏好、授权联网、邮件草稿和记忆门控可用；取消与防剧透不变；默认工程检查通过，并独立报告真实成功率和准确率。未运行真实对照时不得称“已可靠”或“已提升”。

**Scope：** 当前 `ChatController → BookChatService` 主链路、检索适配器、现有记忆/联网/邮件的复用、相关前端状态、回归与评测文档。替换旧深度服务，保留必要的 deadline/取消工具。无新生产依赖、供应商、数据库迁移、环境配置、索引缓存或多 Agent。

**Risks：** provider 对原生 tool calling 的兼容性需真实验收；模型可能少检索或误解证据；工具选择仍消耗时间；工具回合内容需要缓冲以免把中间文本当作最终答案；已提交的会话或记忆写入不能因随后取消回滚。

## 2. 已核对事实与技术选择

- 快速路径已通过确定性规则处理简单问题；只有复杂/追问才使用 Planner 模型。快速规则保持不变；深度不得在理解意图前按规则强制初始化检索，也不增加所有问题必经的独立计划模型。
- 旧 deep 必经 plan、retrieve、check，plan/check 各 5 秒；这足以构成响应慢时的失败条件，但单行超时日志不能定位用户那次具体阶段。
- 当前生产聊天记忆经 `MemoryService.buildBookAgentContext/processAndStoreBookMemory`，不是由 MCP memory 工具提供。当前 MCP 已注册 Tavily，聊天通过 `ExternalResearchService` 使用；邮件通过 `prepare_email` 生成草稿。恢复这些已有能力，不新建记忆存储。
- MCP 配置 allowlist 不能代替聊天业务授权；不能把发现的全部工具直接绑定到含私人正文的模型。未接入的其他 MCP 工具需单独定义消费者、参数及数据边界。

选择“主模型理解本轮请求 + 原生工具调用 Agent 循环”。2026-10-07 修正：原“规则初始化”使未命中词表的普通对话在主模型之前就被强制检索；初次动作与补充动作统一交给同一受控工具循环，不能靠扩充例外词表修补。仅扩大旧超时不能消除多余流程；另建多 Agent 增加协调与评测变量。所选方式复用已有检索与业务权限，去掉独立 JSON 计划和证据检查模型。

## 3. 执行流程

1. 服务端 resolve 并冻结 owner/book/session/version/ceiling，申请一份运行租约，取得有界历史。
2. 主模型先接收原问题与有界近期对话，不调用 Planner 分类或预先检索。近期对话用于理解指代与本轮意图，不自动延续上轮任务；确认、感谢、结束交流等可直接简短回答。回答详略设置不要求每轮深入分析。
3. 需要新的小说事实时先请求 book_search；需要近期对话未提供的已确认偏好/笔记时请求 memory_recall。模型决定是否需要资料，但身份、范围、许可与预算始终由服务端决定。没有初次自动书内检索或自动记忆召回。
4. 主模型看到当前证据、必要历史、记忆与本次可用工具，通过原生 `tool_calls` 决定初次检索/补检/召回/授权联网/草稿，或直接给出最终回答；无独立 plan/check 调用，无自由文本 JSON 决策解析。
5. 工具参数先严格校验，再由闭包注入可信作用域。顺序执行，每回合最多一个调用，结果以对应 ToolMessage 返回；模型不输出数据库条件或授权参数。
6. 工具回合的文本不展示、不落库。完整回合确认无 tool_calls 时进入独立且禁用工具的最终回答回合，按第 6 节逐段输出；生成前及展示前复核书籍状态和进度收紧。到达回合/无进展上限时，保留回答预算，以禁用工具的最后一回合根据已有依据回答并说明缺口。
7. 只写原问题和最终回答一次；原始用户消息按现有记忆门控处理一次。模型产生的查询、草稿正文、工具结果和“思考”不得自动成为记忆。

小说事实始终需要本次可访问原文，记忆和联网不能替代。工具不返回依据时应回答“当前可见范围未找到”，而不是继续重复检索。模型对证据是否充分的判断通过真实评测检验，不用 RRF 分数作为置信度，也不承诺仅靠 Prompt 保证事实正确。

## 4. 工具与数据边界

| Agent 工具 | 允许输入 | 服务端执行与限制 |
| --- | --- | --- |
| `book_search` | 1–3 条查询，每条 1–2,000 字符 | 当前 book/version/ceiling 的 Milvus + 可见 BookChunk BM25；原问题完整进入主模型，检索词由模型生成并经过工具 schema 校验 |
| `memory_recall` | query（1–2,000 字符）、policy（preferences/book_notes） | owner/book/session 由服务端注入；最多 5 条、每条 500 字符，只取已确认偏好/本书记忆；不把笔记当作原著 |
| `request_external_research` | 空对象 | 仅本次 externalResearch=true 暴露；复用隔离联网路由，只输入原问题（邮箱脱敏）和必要书名，不输入原文、记忆、历史或主 Agent 生成的搜索词 |
| `prepare_email` | 既有收件人/主题/纯文本结构 | 仅当前原始问题命中既有直接邮件意图时暴露；复用草稿校验和账号邮箱占位符；不调用 SMTP，投递仍由用户确认 |

`request_external_research` 是应用适配器，下游保持 `tavily_search` allowlist。联网路由继续可选择不搜索；其现有失败语义为显式提示“外部资料不可用”后基于书内可见原文继续，不能把联网失败当作成功。没有本次授权时不加载 MCP 工具。

记忆写入不是任意 `memory_write` 工具：成功后服务端处理原始用户消息，继续敏感内容拒绝、确认/提案及去重规则。纯“请记住”也能得到符合真实写入结果的反馈，不能先说保存成功再吞掉错误。模型无法修改 owner/book 或把未确认提案当作已确认记忆。记忆和仓储可加兼容的可选 AbortSignal；快速调用不传时行为不变。

## 5. 有界资源与失败语义

| 项目 | 修正版上限 |
| --- | --- |
| 在线 deadline | 90 秒，取得租约起，覆盖工具、回答和持久化 |
| 主 Agent 模型回合 | 最多 4 次，包含最终回答；最多前 3 次可有工具，第 4 次无工具 |
| 单次主模型期限 | min(当前 openai.requestTimeoutMs，30 秒，剩余在线时间)；默认现有 20 秒，不再硬编码 5 秒 |
| 回答保留时间 | 补充动作仅在剩余时间大于 30 秒时开始；最后回合仍受单次期限，留余量持久化 |
| 主模型输出 | 每回合最多 2,400 tokens；maxRetries=0，无供应商/模式切换 |
| 授权联网路由模型 | 最多 1 次；沿用现有隔离策略，计入总调用日志；不可重复联网 |
| 书内检索 | 模型请求的初次检索与补检合计最多 3 次、9 条 Embedding 输入，不重试 |
| 主 Agent 工具执行 | 最多 3 次，书内检索、记忆、联网和草稿均计入同一预算；无额外初始化动作 |
| 记忆召回 | Agent 请求召回最多 2 次，最终去重后最多 5 条/2,500 字符 |
| 邮件草稿 | 最多 1 次；无真实发送 |
| 记忆门控 | 正常完成最多 1 次，来源仅原始用户消息；普通问答不得启动写入 |
| 记忆派生 Embedding | 仅符合现有持久化规则时，最多 1 个文本/1 次请求；deep 使用无重试 client，quick 原配置不变 |
| 最终原文 | 最多 8 块/12,000 字符、每章最多 3 块，跨轮 ID/offset 去重；累计候选最多 24 块/36,000 字符 |
| 每次模型输入/历史 | 40,000 字符；近期最多 8 条/12,000 字符；保留原问题，不悄悄截短 |
| 等待心跳 | 每 10 秒固定状态，不声称完成检索或取得证据 |

主模型同回合给出多个工具调用：不执行，对每个有效 tool_call_id 返回对应的固定 `MULTIPLE_TOOL_CALLS` ToolMessage，不能留下无结果的调用破坏 SDK 协议；合法工具参数错误返回固定 `INVALID_TOOL_ARGUMENTS`，最多允许一次后续模型回合修正，不重试外部执行。工具调用缺 ID、未知/未授权工具、scope 注入或来源边界变化直接失败，不提供绕过机会。重复查询或重复记忆调用不再次访问外部；无新证据结束补检。预算耗尽是明确的有限依据停止，provider 超时/检索失败/取消是错误，不借机切 quick。

补检到预算上限后重建最终上下文，只保留有界最终证据；不让已移除片段残留在旧 ToolMessage 正文。工具协议记录保留 ID 和固定元数据，正文只在当前证据 envelope 中出现。每次外部调用前后、迭代器 next/yield、锁等待后及持久化前检查 signal。memory read/write 迟到不能继续后续写入或派生向量调用；已提交数据库写入或已发出的 SDK 调用不可逆，必须如实记录。

保留公开稳定错误码，诊断增加固定 stage/reason（bootstrap/agent/book_search/memory_recall/external_research/email/history/memory_commit）。超时须有具体阶段；无原文是正常未找到，不等同超时。记忆门控失败时回答仍可完成，但发送既有 thinking 明确“回答已完成，记忆未确认保存”，不伪造 memoryUpdate；显式记住请求的最终正文不得预先承诺已保存。日志不记录完整异常、正文、问题、账号标识、工具参数或凭据。

## 6. 流式与兼容性

HTTP 仍为可选 quick/deep，responseDepth 仍仅影响详略。移除 deep 与联网/邮件的组合拒绝；恢复输入框联网选项。保持 owner 和 scope 不在客户端请求体中。

2026-10-07 用户确认修订：原生工具回合缓冲文本，不展示候选回答；确认不再调用工具后，单独启动禁用工具的最终回答回合，逐段通过 SSE 输出。最终回合包含在既有最多四次主模型调用中，不增加上限；部分请求会多一次模型调用并增加延迟及费用。预算强制结束时直接进入最终回合。每段正文展示前复核书籍状态、索引版本和阅读上限；取消、越界、意外工具调用或截断返回错误，不保存未完成回答。显式记忆保存请求仍等门控完成后展示，避免提前声称保存成功。不得把混杂工具调用的中间回答落库或发送邮件。

快速/深度选择在当前会话内保持，发送后不重置；切换书籍、会话或重新打开助手面板恢复快速。联网与全书检索仍是单次授权，发送后清除。

2026-10-07 全书问答上下文修正：证据容器放在原始问题之前，原始问题保持为最后一条用户请求，其后仅保留合法的工具协议消息。最终回答指令属于系统策略，不追加伪用户请求。系统策略明确本轮服务端 resolve 批准的章节上限，历史中的旧范围不能覆盖；空证据容器表示尚无本轮证据，不表示已经检索且没有原文。小说问题仍由主模型通过合法工具调用请求检索，不因本次修改强制所有闲聊检索。回答不得展示内部证据 JSON 或系统规则。全书授权只改变本轮检索上限，不修改长期阅读进度，未授权时仍拒绝上限之后的引用。

保留 thinking/references/externalReferences/emailDraft/memoryUpdate/error/DONE。只有最终被采用且通过复核的片段进入 references；不要展示所有历次召回候选。已有 runSummary 的 stopReason 枚举保留；satisfied 表示正常结束，不再声称独立证据检查证明充分。仅有书内检索（retrievalRounds≥1）时发送 summary，纯闲聊/记忆可省略这个可选事件，避免旧客户端 1–3 轮校验失效。前端改为“已完成本次检索”/“检索达到上限，依据可能有限”，失败不显示“已完成检索”。当前会话陈旧事件隔离及用户停止保持。

## 7. 验收与交付

工程硬门（按 2026-10-07 流式修订）：无需资料的对话一个工具判断回合和一个最终回答回合、零工具完成；单点事实一次检索、三个模型回合完成；初次检索必须发生在模型的合法工具请求之后；模型调用总数仍最多四次。无 plan/check 模型；5–10 秒响应不会被旧 5 秒期限杀死；空语料、零增益、停止、超时、旧版本、章节上限、无授权工具、恶意参数、重复回合、记忆与邮件重复副作用均有拒绝/轨迹测试。工具仅在对应授权下可见，运行角色不取得其他业务 skill。现有 quick 的请求、检索和工具回归保持。

真实评测主对照为开工时 quick（Q）、旧 deep（D0）、新 Agentic deep（D1），冻结各自源码 hash、模型/provider、历史、进度、题目和原文预算。旧 deep 可用受控冻结输出，不需保留生产切换参数。之前纯向量 B0 对混合路径的验收仍独立保留，不能由本次 Q/D1 替代。

先审定 24 题 smoke：简单事实 8、跨段关系 4、历史追问 3、偏好/记忆 3、联网 2、邮件 2、无依据/防剧透 2；再审定现有 120 题及 40/80 开发/验收分割，排除仅靠模板变体造成的虚假样本量。至少三本合成/获准小说；简单题原文必须明确，不能靠模型常识判“主角”。新增工具场景用受控 fixture，不虚构外部调用质量。

效果阶段门是目标而非已测结论：smoke 的 8 个简单事实题及记忆/工具授权用例各三次全部完成；模型明确支持 native tools；新模式在冻结复杂题子集的正确答案率相对 Q 至少提高 10 个百分点，简单题正确率不低于 Q；无依据事实率不高于 Q；安全违规为 0；完成率≥95%；简单题 firstContent/总耗时 p95 各不超过 Q 的 1.3 倍。给出改善/退化题数、按题配对区间及人工盲评；区间跨 0 时称证据不足。若延迟因缓冲不达标，应先在开发集改流程，不能放宽验收阈值或提高隐藏预算。

默认测试不连接实际 DB/Milvus/模型/SMTP。真实测试继续独立数据库、book/memory 两个 test_* 集合、上传目录及受控启动指纹；费用、语料与目的地须单独授权。工具 E2E 默认 fake MCP 和 fake SMTP，真实联网或投递另获授权；前端“确认发送”不能因评测自动点击。未满足隔离条件则交付工程成果、标真实未验收，不清库或改 .env。

交付新编排、业务适配器、回归、更新的测试入口和报告。删除不再使用的旧 deep plan/check 服务与其专属测试，不删除通用混合检索、安全回归或旧评测记录；旧记录注明被替代部分。回退只回应用代码，保留历史/记忆数据，不执行数据删除。
