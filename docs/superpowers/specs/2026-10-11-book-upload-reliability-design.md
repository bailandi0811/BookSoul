# 小说上传与并发处理实施方案

日期：2026-10-11。用户已授权按讨论方案实施；本文件记录本次交付边界，不代表生产配置或数据迁移已经执行。

## 目标与范围

- 新客户端使用私有 OSS 上传会话；小于 10 MiB 单次 POST 直传，10–50 MiB 使用 5 MiB 分片，浏览器最多三片并发。
- 支持重新选择原文件后恢复上传；服务器查询 OSS 已上传分片，不信任客户端分片完成声明。客户端保存会话 ID 和文件指纹，不保存签名 URL、凭据或正文。
- 确认接口幂等，服务器验证真实文件大小、格式与 SHA-256；同用户重复文件返回已有书籍，不跨用户去重或共享文件。
- 每用户最多两个有效上传会话，源文件与在途预留合计最多 1 GiB；确认阶段全局最多四路。每用户最多一个 RUNNING 导入任务，全局最多四个；worker 单进程保持一个任务，多个进程通过数据库争抢任务。文件传输与模型处理分别限流。这些是保守初始值，尚无真实负载容量结论。
- 新源文件存入 OSS，原有本地文件和 multipart API 保留兼容。不修改现有环境或部署配置，不搬迁、删除既有用户文件。
- 增加执行租约身份与独立心跳，隔离被接管的执行者；取消和失去租约后禁止提交结果。
- 本次保留 READY 的阅读/聊天契约。正文先可读、跨用户秒传、完整索引升级和批次持久恢复不在本次范围。

## 上传与确认

`POST /api/books/uploads` 创建或恢复当前用户会话，`GET /api/books/uploads/:id` 返回短期上传授权及 OSS 已完成分片；`POST .../:id/commit` 完成分片、固定独立源对象并验证后，在同一事务创建 Book/任务并提交会话；`DELETE .../:id` 取消尚未提交会话。

会话包含 owner、客户端声明的大小/哈希、服务端生成的对象路径、OSS UploadId、有效期、确认租约及 bookId。声明的哈希只用于恢复匹配，入库哈希由服务端重新计算。确认租约防止多个请求同时合并/建书；响应丢失时重复确认返回同一结果。权限失败和存储不可用显式返回错误，不自动退回旧上传链路。

暂存对象与正式对象均私有。正式对象使用每次确认独立的随机路径，所有候选清理路径持久记录，防止旧执行者覆盖新结果。服务器流式下载到独立临时目录，限制读取字节数和总耗时；验证后删除临时文件。源文件不提供公共读取 URL。分片使用 V4 URL 签名绑定浏览器自动生成的 Content-Length，并固定 Content-Type，防止用小文件配额上传超大分片；参见 [OSS V4 签名规范](https://www.alibabacloud.com/help/en/oss/developer-reference/add-signatures-to-urls)。

## 生命周期与并发

上传会话有效期 24 小时，签名有效期最多 5 分钟。用户行锁串行化配额预留和提交，数据库条件更新串行化确认。超过配额返回可行动的 429。确认总耗时和租约均有界；到期后允许重试，旧请求不能提交。

后台任务领取使用 PostgreSQL 短事务 advisory lock 串行化全局与同 owner 的领取决策，并用独立 leaseToken 校验心跳、状态提交和失败更新。不同执行构建使用隔离的向量版本，不能按共享版本清理其他执行结果。单 worker 保持一个任务；模型请求已有超时/有限重试并传播取消信号。全局任务上限只限制并发，不等同于供应商 RPM/TPM 或费用预算；独立模型用量预算仍需后续实施。

未完成分片和暂存对象配置生命周期清理；应用清理仅针对自己创建、明确到期且无有效确认租约的会话。正式源文件由书籍删除流程清理；未提交的候选源文件通过会话记录清理。已提交会话记录保留以支持响应丢失后的幂等确认。

## 运维与验证

复用既有 OSS 配置与 ali-oss 依赖，不新增供应商。上线前核对私有 Bucket/RAM 权限、CORS 的 POST/PUT 和 Content-Type，服务端合并/列分片/复制/读取/删除权限以及暂存生命周期。小说源文件将发送到所配置 OSS，保留至删除书籍；网络/存储/Embedding 可能收费。现有 OSS 未配置时新上传明确不可用。

Prisma 采用新增迁移，先停止会写库的旧进程，备份并审核 SQL 后由部署者执行。开发时仅生成客户端类型，不运行迁移、不读取 `.env`，不连接真实服务。

回归覆盖：小文件/分片边界、断点恢复、错误文件指纹、重复确认、确认响应丢失、跨 owner 拒绝、并发配额、未完成分片、超限对象、租约接管、取消及旧客户端兼容。默认质量门必须保持数据库无关；真实 OSS 和数据库验收只有在目标隔离验证和外部写入授权满足后执行。

## 前端取消恢复与界面修正

上传授权响应失败时，浏览器可能只保留 requestId，而服务端已创建上传会话。用户取消该会话后重选原文件，原客户端只处理 GET 会话的 404/410，遗漏 POST 复用 requestId 返回 410，导致反复显示“上传已过期或取消”。现已在服务端明确返回 410 时更换 requestId 并只重新创建一次；503、网络错误继续保留幂等键，不自动重建，账号切换后禁止继续发起请求。

上传入口恢复原有空闲文案和卡片结构，阶段状态复用原进度行；未完成任务放在卡片外且默认折叠，无任务时不占用界面。新增回归覆盖授权响应丢失后取消重选、过期会话、恢复次数限制、临时错误和账号切换，以及任务折叠与取消。相关 14 个用例通过；未据此宣称真实 OSS 上传或浏览器视觉验收完成。

修正后客户端完整质量门通过：62 个测试文件、284 个测试，lint、类型检查和构建通过。只读外部诊断发现本地签名生成正常，但当前凭据对已记录暂存对象的 HEAD 请求返回 403 AccessDenied；这会阻断上传授权，具体拒绝策略须由云管理员核对，不能仅修复客户端后宣布上传已恢复。

为当前 AccessKey 所属 RAM 用户/角色补充的目录级权限模板见[OSS 权限示例](../../deployment/book-upload-oss-policy.example.json)，把 `<OSS_BUCKET>` 替换为现有配置的 Bucket 名称，作为补充策略绑定，保留原有头像等权限。若已有显式 Deny、来源 IP 或 VPC 条件限制，新增 Allow 不会覆盖拒绝，需管理员核对有效策略。Bucket 保持私有；本轮未修改真实 RAM/Bucket/CORS 策略或环境配置。HEAD 对应 `oss:GetObject` 等操作映射依据 [OSS 官方权限表](https://www.alibabacloud.com/help/en/oss/user-guide/authorization-syntax-and-elements)。授权后先复测元数据读取，再验收浏览器上传及 CORS；本次不提供整 Bucket 全权限。

## PostObject 文件类型修正（2026-10-12）

用户完成 RAM 授权后，后续元数据读取返回预期的 NoSuchKey，历史取消会话已完成清理。浏览器直接上传仍返回 403；OSS 响应明确给出 `0006-00000227`，失败条件为 `$Content-Type = application/epub+zip`，实际值是 `application/epub`。该失败来自浏览器文件类型与上传签名策略不一致，不能通过扩大 RAM 权限处理。

PostObject 授权改用 `x-oss-content-type` 并签名绑定该字段，覆盖浏览器自动推断的类型；前端发送文件时按扩展名统一为 EPUB 的 `application/epub+zip` 或 TXT 的 `text/plain`，保留文件字节与名称，file 字段继续放在最后。精确字节数、私有 ACL、禁止覆盖和有效期条件保持不变。依据 [OSS PostObject 官方说明](https://www.alibabacloud.com/help/en/oss/developer-reference/postobject)。

前端从有界 OSS XML 响应识别策略不匹配、授权过期、签名错误及凭据/访问拒绝，只展示固定提示，不显示原始 Message、对象路径或凭据；失败不自动重试，不继续确认书籍。回归覆盖实际的 `application/epub`、ZIP、空 MIME、TXT 类型差异，以及错误分类和脱敏。真实浏览器上传与后续索引仍须实际验收，单元测试不代表真实 OSS 成功。
