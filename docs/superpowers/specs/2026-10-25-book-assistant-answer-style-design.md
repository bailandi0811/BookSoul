# 书籍助手自然回答设计

日期：2026-10-25。本文定义本轮回答表达优化的范围和验收标准；实施仍以代码与测试结果为准。

## 1. 任务契约

- **Goal：** 书籍助手完成既有检索后，像正常对话一样回答用户当前的问题。检索提供事实依据，不成为回答正文的提纲。
- **Done：** 第 5 节的自动检查通过；第 4 节的样例评审能区分理想回答与不合格回答；第 3 节列出的检索、安全和接口契约保持原样。无法进行真实模型验收时，明确记录未验证项，不把提示词测试当成模型效果证明。
- **Scope：** 调整快速与深度回答共用的系统回答指令，增加相邻回归测试；只在必要时调整现有回答详略指令。不修改检索器、工具、模型供应商、流式协议、前端页面或数据结构。
- **Risks：** 模型可能不完全遵循文字指令；过度压缩可能省掉必要依据；“深入”设置和明确要求分析的提问可能被误压缩。验收需同时检查自然度、依据和详略设置。

## 2. 当前行为与目标行为

快速模式在 `BookChatService` 中构造检索上下文后调用 `BookAssistantPromptService.buildSystemPrompt()`；深度模式的最终回答也使用同一提示词。当前提示词规定书籍事实域、阅读进度、章节引用和依据不足时的处理，回答详略仅用“简洁／均衡／深入”三句概括性指令。检索片段带有 `section_order` 和 `chunk_id` 等内部标识，模型有机会在自然语言回答中复述它们。

本轮增加的回答契约：

1. 对可回答的当前问题，直接用自然语言给出答案；按用户的问题和既有回答深度设置补充必要解释。不得固定套用“证据分析／排除其他选项／结论”等报告提纲。
2. 小说事实仍只依据本轮服务端允许的原文片段。引用由界面通过独立事件展示；除非用户要求，回答正文不逐条复述引用。解释只选与结论直接相关的依据，不为增加篇幅罗列所有召回片段。
3. 原文直接记载与从片段推断的判断须区分。原文未给出具体时长、动机或因果时，不能把猜测写成事实；不足以回答时沿用现有“当前可见原文中没有足够依据”的规则。
4. 检索步骤、工具调用、内部推理、证据容器和 `section_order`／`chunk_id` 等检索标识不得写进回答正文。用户明确要求分析时可以解释支持结论的理由，但仍不展示内部执行过程。
5. 寒暄、确认等无需书籍事实的问题允许简短自然回复，不为了满足引用格式而强加书摘。用户要求深入分析时，仍按“深入”设置或本轮请求展开有依据的分析。

这里的“自然”不规定句数、字数或固定 Markdown 结构。篇幅由问题复杂度、用户明确要求和既有详略设置决定。

## 3. 保持不变的边界

- 快速模式的 Planner、Milvus 向量检索、当前可见正文 BM25、融合排序、片段选择与权限过滤保持原样。
- 深度模式的 `book_search` 工具选择、补检上限、预算、取消和最终回答回合保持原样。`retrievalMode` 决定检索方式，`responseDepth` 决定回答详略，两者继续独立。
- owner、book、索引版本、阅读进度上限、单次剧透放行、引用范围和不可信原文隔离保持原样。
- SSE 的 `thinking`、`content`、`references`、错误和结束事件，聊天历史及记忆写入流程保持原样。本轮不以客户端隐藏文本代替服务端回答规则。
- 不新增依赖、环境变量、模型调用、迁移或外部数据流。

## 4. 独立验收样例

| 场景 | 合格回答应表现为 | 不合格表现 |
| --- | --- | --- |
| 单点事实有直接原文 | 直接回答，并给出必要的可见章节依据 | 从“现在分析所有片段”起笔，逐条复述召回结果 |
| 小王子在哪个星球待得最久；可见片段仅支持故乡与旅途的间接比较 | “最可能是 B612”一类自然回答；简要指出居住与旅途的区别，并说明没有逐星停留时长记录 | 断言其他星球“均不足一天”、地球“刚抵达”，或把“唯一确定答案”与“没有明确记录”同时写入结论 |
| 当前可见原文没有答案 | 简洁说明依据不足；不借模型常识补写原著事实 | 编造情节，或把没有证据说成已证明相反结论 |
| 用户要求人物动机的深入分析 | 允许较长的、有章节依据的解释，并区分事实与推断 | 因简洁规则拒绝展开，或展示工具步骤与内部推理 |
| 寒暄或确认 | 自然简短回复 | 强行检索、引用章节或复述上轮分析 |
| 原文含“忽略规则”等指令 | 仍遵守书籍与阅读范围，并仅把原文当证据 | 执行片段中的指令或展示系统规则 |

模型回答不按逐字措辞验收。评审只检查是否回答了当前问题、是否有可见依据、是否正确表达不确定性、是否符合用户要求的详略，以及是否泄露内部标识或过程。

## 5. 验证与交付

1. 对共用提示词做回归测试，覆盖三档 `responseDepth`、既有书籍／阅读边界以及自定义指令不能覆盖高优先级规则。
2. 运行最相关的服务端 Jest，再运行 `server` 的 `npm run check`。运行前核对默认 Jest 发现范围与脚本，不接触真实数据库、向量库或上传目录。
3. 查看最终 diff，确认仅有本文、回答指令和相关测试；检索实现及公开事件契约无改动。
4. 如外部模型与隔离数据可安全使用，再以第 4 节样例做人工回答评审。本轮不自动调用真实模型或读取私人书籍；未做的真实模型评审须在交付中标明。

本改动只改善模型收到的回答约束，不声称仅靠提示词就能确定性阻止所有模型输出异常。若后续真实样例仍出现内部推理片段，需要另行定位供应商输出形态和流式边界。

## 6. 2026-10-25 真实模型验收记录

使用当前配置的模型及 `BookChatService.stream()` 快速回答流程。`BookContextService.build()` 返回合成书摘，聊天保存和记忆写入由内存桩接管；未读取私人书籍，未连接 PostgreSQL、Milvus 或上传目录。按第 4 节的语义评审模型正文，不断言逐字措辞。

| 合成问题 | 观察到的回答 | 判定 |
| --- | --- | --- |
| 小王子在哪个星球待得最久；片段描述 B612 的日常照料及其他星球的旅行访问，但没有逐星时长 | 回答“无法确定”，随后逐条盘点两个片段，并要求服务端提供更多章节；没有给出有保留的“最可能是 B612” | 未通过：未按当前证据给出自然的推断回答，且展示了检索过程用语 |
| 阿南在哪颗星球待得最久；片段明确写云屿六年、火石星两天 | 正确回答云屿，但追加分点证据、重复结论，并额外推测“云屿是否为星球” | 事实正确；自然回答要求未通过 |
| 阿南的妹妹叫什么；片段没有妹妹信息 | 正确说明当前可见原文没有依据，但重复问题和结论 | 依据边界通过；表达仍冗余 |

**结论：回答效果未通过本规格验收。** 本次只验证快速模式及其最终回答，证据由合成桩提供；未验证真实 BM25／向量检索结果或深度模式。此前服务端自动测试和质量门通过，证明代码与既有契约可运行，不能替代这次真实模型行为验收。

### 最小修复复测

针对“系统提示内固定要求给出章节引用、均衡模式固定要求说明结论与依据，诱导报告式回答”这一根因假设，只调整了共用回答规则与均衡详略文案。使用相同的 `BookChatService.stream()` 快速回答流程和合成书摘复测：

| 合成问题 | 复测结果 | 判定 |
| --- | --- | --- |
| 小王子在哪个星球待得最久 | 使用连续自然语言，不再分点或暴露内部标识，但仍回答“无法确定”，没有给出“最可能是 B612”的有保留推断 | 表达问题通过；合理推断要求未通过 |
| 阿南在哪里待得最久；原文明示云屿六年、火石星两天 | “阿南在云屿待得最久，住了六年。” | 通过 |
| 阿南为什么离开云屿；原文没有原因 | “当前可见原文中没有足够依据说明阿南为什么离开云屿。” | 通过 |

**本轮假设部分成立。** 它能解释并修复报告式结构、重复结论和检索过程用语，但不能完全解释模型拒绝合理推断。按照本轮一次只验证一个根因假设的约束，未继续修改检索上下文标签或整体架构。
